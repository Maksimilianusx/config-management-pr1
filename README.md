## 1. Назначение проекта

Проект представляет собой графический эмулятор командной оболочки UNIX-подобной ОС, написанный на **Python** с использованием **Tkinter**. Программа принимает команды пользователя, работает с виртуальной файловой системой (**VFS**), загружаемой из ZIP-архива, и записывает историю выполнения команд и ошибки в **XML-журнал**.

Работа выполнена последовательно в **пять этапов**. Каждый этап представлен отдельным коммитом Git, поэтому преподаватель может проверить развитие проекта от простого интерфейса до файловых команд.

## 2. Требования

- Windows и PowerShell (команды запуска ниже рассчитаны на Windows).
- Python **3.9 или новее** с установленным модулем Tkinter (обычно входит в стандартную установку Python для Windows).
- Git — для получения репозитория и переключения между коммитами.
- Интернет нужен для первоначального скачивания репозитория; работа самой программы происходит локально.

Сторонние библиотеки через `pip` устанавливать не требуется: используются модули стандартной библиотеки Python.

Проверить установку:

```powershell
python --version
git --version
```

## 4. Этапы выполнения

### Этап 1. Графический REPL

Создано окно эмулятора на Tkinter. Заголовок содержит реальные имя пользователя и имя компьютера. Реализованы ввод и разбор команд, раскрытие переменных окружения (например, `$HOME`), обработка неизвестных команд и `exit` для завершения. На этом этапе `ls` и `cd` — **заглушки**: они показывают полученные аргументы, но не выполняют файловые операции.

### Этап 2. Параметры запуска и журналирование

Добавлены параметры командной строки `--vfs`, `--log`, `--script`. Разработан XML-журнал событий с датой и временем, исходной командой и сообщением об ошибке. Добавлена обработка стартового сценария — текстового файла с командами, выполняемыми последовательно. Подготовлены тестовые скрипты и проверки парсера.

### Этап 3. Загрузка виртуальной файловой системы

Реализовано чтение ZIP-архива в память без распаковки его файлов в рабочую файловую систему. Подготовлены три примера: `files`, `minimal`, `deep`. Скрипт `scripts/build_vfs.py` создаёт архивы из исходных каталогов, после чего запускается эмулятор. На историческом коммите третьего этапа `ls` и `cd` ещё остаются заглушками.

### Этап 4. Команды работы с VFS

Команды `ls` и `cd` начинают работать с виртуальными каталогами. `ls` показывает содержимое текущего или указанного каталога; `cd` изменяет текущий каталог внутри VFS. Добавлены `date` (текущая дата и время) и `rev` (переворот текста). Реализована обработка ошибок неверных аргументов и отсутствующих каталогов. Скрипт `run_stage4.bat` самостоятельно собирает необходимые ZIP-архивы.

### Этап 5. Создание файлов в памяти

Реализована команда `touch`, которая создаёт пустой файл в VFS или обновляет дату модификации существующего файла. Изменения происходят **в памяти** и не записываются обратно в ZIP. Добавлены варианты вывода `ls -1` (один объект на строку) и `ls -l` (развёрнутый список с виртуальными метаданными). Проверяются ошибки, например отсутствие родительского каталога или неправильное число аргументов.

## 5. Быстрый запуск последней версии (этап 5)

Откройте PowerShell и выполните:

```powershell
git clone https://github.com/Maksimilianusx/config-management-pr1.git
cd config-management-pr1
.\scripts\run_stage5.bat
```

Скрипт сам создаёт архивы и запускает графическое окно эмулятора. **Команды следует выполнять из корневой папки проекта**, поскольку BAT-файлы используют относительные пути. Для текущей версии рекомендуется `scripts/run_stage5.bat`, а не старый `run.bat`: в новой версии параметр `--vfs` обязателен.

## 6. Запуск отдельных этапов

В приведённых ниже примерах команда запуска выполняется **в корне соответствующей версии проекта**.

| Этап | Команда запуска | Особенность |
|:---:|---|---|
| 1 | `.\run.bat` | GUI, разбор команд, заглушки |
| 2 | `.\scripts\run_with_params.bat` | Параметры, журнал XML, сценарий |
| 3 | `.\scripts\run_vfs_files.bat` | ZIP-VFS и заглушки `ls`, `cd` |
| 4 | `.\scripts\run_stage4.bat` | Рабочие `ls`, `cd`, `date`, `rev` |
| 5 | `.\scripts\run_stage5.bat` | `touch`, `ls -1`, `ls -l` |

Чтобы открыть **конкретный этап** отдельно, удобно использовать `git worktree`, не изменяя текущую ветку:

```powershell
git worktree add --detach ..\check-stage3 6c1826f
git worktree add --detach ..\check-stage4 61a214f
git worktree add --detach ..\check-stage5 30f4823
```

После этого перейдите в нужную папку и запустите соответствующий BAT-файл, например:

```powershell
cd ..\check-stage4
.\scripts\run_stage4.bat
```

**Примечание для этапа 2:** скрипт `run_with_params.bat` использует пример `demo_vfs.zip`; в соответствующей исторической версии он служит прежде всего демонстрацией параметров запуска. Для просмотра возможностей третьего и следующих этапов используйте их отдельные BAT-файлы.

## 7. Поддерживаемые команды (этап 5)

| Команда | Назначение | Пример |
|---|---|---|
| `ls` | Показать содержимое текущего каталога | `ls` |
| `ls путь` | Показать содержимое указанного каталога | `ls /level1` |
| `ls -1` | Один файл или каталог на строку (**цифра 1**) | `ls -1` |
| `ls -l` | Подробный список (**строчная латинская l**) | `ls -l` |
| `cd путь` | Перейти в каталог VFS | `cd level1` |
| `cd ..` | Подняться на один уровень | `cd ..` |
| `date` | Показать текущую дату и время | `date` |
| `rev текст` | Вывести текст в обратном порядке | `rev hello world` |
| `touch имя` | Создать файл или обновить время изменения | `touch note.txt` |
| `exit` | Закрыть окно эмулятора | `exit` |

В выводе `ls -l` права доступа и имя владельца виртуальные, не являются правами реальной Windows. Реальная файловая система компьютера не изменяется командой `touch` в эмуляторе.

## 8. Проверка работы

### Проверка VFS и команд (этап 4)

```text
ls
cd level1
ls
cd level2
ls
cd level3
ls
date
rev hello
cd missing
abc
exit
```

**Ожидаемое поведение:** `ls` показывает объекты VFS, `cd` изменяет виртуальный текущий каталог, `rev hello` выводит `olleh`; ошибки неизвестной команды и несуществующего каталога обрабатываются без аварийного завершения.

### Проверка создания файлов (этап 5)

```text
ls
ls -1
ls -l
touch test123.txt
ls -1
ls -l
touch test123.txt
touch missing/test.txt
touch
exit
```

**Ожидаемое поведение:** `test123.txt` появляется в списке, повторный `touch` не вызывает ошибку, создание файла в отсутствующем каталоге и вызов `touch` без аргумента сопровождаются сообщением об ошибке.

### Проверка парсера и синтаксиса Python

Из корня проекта:

```powershell
python -m unittest discover -s tests -v
python -m py_compile src\main.py
```

### Проверка чистого запуска без ZIP-архивов

В новой копии GitHub каталог `vfs/` содержит исходные папки, но не готовые ZIP. Команда `.\scripts\run_stage5.bat` должна самостоятельно создать архивы и открыть эмулятор. Аналогично работает исправленный скрипт этапа 4.
